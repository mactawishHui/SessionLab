# 0.6.2 首次加载优化验收（2026-10-21）

已在日常 Chrome 的扩展详情确认安装 0.6.2；没有新增权限。31 项自动检查通过（16 项原生会话、15 项缓存/并发/跳转检查）。

## 测量结果

本地 Chrome for Testing 148.0.7778.96，同一 Profile、96 个静态资源、2000 条无关虚构 Cookie；所有响应 no-store，每轮服务器实际收到 96 个资源请求，未利用热缓存。每类交替运行 5 次，表内是中位 wall time。

| 场景 | 0.6.1 | 0.6.2 | 减少 |
|---|---:|---:|---:|
| 资源冷加载 | 347.8ms | 156.0ms | 55% |
| 冷加载 + 大量站点存储写入 | 540.2ms | 159.8ms | 70% |

普通标签对照分别为 112.8→120.5ms、113.6→118.6ms，说明插件仍有开销。单次新建分组冷打开观测为 416.5→239.0ms；该项只有一次观测，不能视为稳定中位数。

日常 Chrome 中，优化前 401 次、优化后 879 次资源请求的分段计时显示：下载后等待分组处理的 responseQueue 平均 366→2ms，最大 1858→54ms；元数据等待平均始终约 1ms，因此没有删除等待逻辑或缩短登录重定向保护。两次采样涉及的页面和请求数不同，只能说明内部排队明显下降，不能当作业务整页提速比例。优化后网络响应头等待平均 142ms、最大 1216ms，实际网站仍受网络、后台和资源依赖链影响。

## 修改

- 批量提交独立请求的临时网络规则，每个请求仍等待自己的 Cookie/Header 规则提交后才发出；同 URL 跨分组仍串行，避免规则串用。
- 相同值的站点存储写入不再产生伪 storage 事件，消除跨页回写循环；Cookie 按域建立索引并保留原同名顺序。
- 合并热路径持久化（约 25ms），移出资源响应队列；“关闭保存”等显式操作仍等待写入完成。进程突然崩溃时不保证最近缓冲改动落盘。
- 资源 Cookie/缓存状态仍按组有序提交，交回 Chrome 的响应完成不再阻塞同组其他资源。
- 优先原生 Base64 编码，并保留兼容回退。
- 关闭分组时兼容已由页面或 Chrome 关闭的子标签；忽略确认已关闭标签的迟到错误提示，保留其他错误。

## 日常 Chrome 验证

- A、B 从普通 BABI 继承登录；分别使用不同测试账号点击“跳转登录 → 火山引擎官网”。新页自动归组，均完成登录。
- B 登录后回看 A，仍显示 A 原账号。
- A 添加虚构测试 Header，本机服务器收到；B 和普通标签回显为空，普通标签虚构账号保持 Original。验证后删除临时 Header。
- A、B 关闭保存均成功，无标签页不存在错误；A 重新打开确认临时 Header 已移除。
- 录屏对应的 ContextSearch 入口，在 A 测试账号下跳到 IAM 跨服务授权页。未点击授权，不把到达该页视为业务场景列表加载完成；未更改云资源、费用或权限。

仍保留原有完整响应缓冲、45 秒超时、32 MiB 响应上限，以及 Worker/Service Worker/WebSocket 限制。此版本仍是 API 层兼容原型，不是浏览器内核安全容器。
